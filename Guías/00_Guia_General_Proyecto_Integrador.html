Cómo funciona

Un proyecto, entregado por fases

Vas a construir un sistema informático real de principio a fin, siguiendo el Ciclo de Vida del Software. El proyecto no se entrega de una sola vez: cada fase es un momento evaluado independiente que recibes y entregas en su propio tiempo. Tu docente te compartirá la guía de cada fase cuando corresponda.

👥
Equipos de 4
Todo el proyecto se trabaja en equipo de 4 integrantes con roles definidos.
🐙
GitHub primero
Todo se sube al repositorio (preferentemente GitHub; Drive como alternativa).
📚
Manuales acumulativos
Los manuales crecen fase a fase y se revisan completos al final del proyecto.
📅
Entregas por tiempo
Cada fase tiene su fecha. No avances saltándote etapas: la documentación se construye en orden.

Organización

Equipo y roles

En un equipo de 4, repartan responsabilidades. Todos revisan el trabajo de todos: los roles organizan, no separan.

🧭
Líder / Documentación
Coordina entregas, arma el ERS y los manuales, controla el repositorio.
🗄️
Backend / Base de Datos
Modela la BD, programa la lógica del servidor y el diccionario de datos.
🎨
Frontend / UI
Diseña las pantallas (Figma) y construye la interfaz del sistema.
🧪
QA / Pruebas
Diseña casos de prueba, reporta errores y prepara la demo y el manual de instalación.
Repositorio

Estructura de tu GitHub

Crea un solo repositorio por equipo y respeta esta estructura de carpetas. Cada fase deja su evidencia en su carpeta. El orden también se evalúa.

estructura del repositorio
# Repositorio del proyecto (uno por equipo)
proyecto-integrador-nombre-sistema/
├─ README.md            # nombre, equipo, descripción y cómo ejecutar
├─ docs/                # FASE 01: ERS, ficha del proyecto
├─ diagramas/           # FASE 02: casos de uso, clases, secuencia
├─ db/                  # FASE 02: modelo ER, script .sql
├─ wireframes/          # FASE 02: prototipos (Figma export)
├─ src/                 # FASE 03: código fuente del sistema
├─ manuales/            # ACUMULATIVO: técnico, sistema, usuario, diccionario
├─ pruebas/             # FASE 04: plan, casos de prueba, bug report
└─ instalacion/         # FASE 04: manual de instalación + datos demo
🐙 Repo público y ordenado
Usa nombres claros, sube imágenes de los diagramas (no solo el archivo editable) y mantén el README.md al día con el nombre del sistema, los integrantes y los pasos para ejecutarlo.

Reglas de oro

🎯
Consistencia total
Si una tabla se llama productos, así aparece en el ER, el diccionario y el código. Siempre igual.
📸
Mostrar, no solo decir
Cada diagrama va como imagen, con título, número de figura y una línea de descripción.
🔄
Versiona todo
Commits frecuentes y descriptivos. Nunca sobrescribas sin dejar rastro del cambio.
🚫
Trabajo propio
Plagiar documentación o copiar el sistema de otro equipo anula la entrega. El repo demuestra quién hizo qué.
📚
Manuales vivos
Los manuales se actualizan cada fase. Al final se revisan completos: no los dejes para el último día.
🤝
Todos participan
La nota es de equipo, pero el dominio es individual. En la defensa, cada quien responde por su parte.
