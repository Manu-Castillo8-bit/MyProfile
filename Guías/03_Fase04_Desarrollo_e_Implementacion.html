Meta de la fase

Construir el sistema, documentando a la par

Aquí el equipo programa el sistema siguiendo los diseños de la fase anterior. Pero no solo se evalúa el código: cada avance se sube al repositorio y se respalda con manuales que crecen junto al proyecto.

Importante

Los manuales son acumulativos

📚 Léelo bien
Los manuales no se entregan al final de golpe: se van cargando y actualizando fase a fase en la carpeta manuales/, preferentemente en GitHub (Drive como alternativa). Al cerrar el proyecto se revisan completos. Quien los deja para el último día, lo paga caro.

Buenas prácticas

Cómo trabajar con Git

Commits con mensaje claro
Describe qué se hizo. Usa el formato tipo: descripción.
Sube seguido, no todo junto
Muchos commits pequeños cuentan la historia del proyecto mejor que uno gigante.
Usa .gitignore
No subas node_modules/, contraseñas ni archivos pesados generados.
Actualiza el README
Que cualquiera pueda clonar el repo y saber qué es y cómo correrlo.
ejemplos de commits
git commit -m "feat: registro de productos con validación de stock"
git commit -m "fix: corrige cálculo del total en la venta"
git commit -m "docs: actualiza manual de usuario, módulo de ventas"

Entrega

Cómo y dónde entregar

Comparte el enlace del repositorio. El docente revisa el código, los commits y los manuales directamente en GitHub.

⚠️ Errores comunes
Subir todo el código en un solo commit el día de la entrega (no muestra el proceso), dejar los manuales vacíos, o que el diccionario de datos no coincida con la base de datos real. Programa y documenta: las dos cosas valen.
